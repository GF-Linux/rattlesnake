# Os dados no ratt db (fase 2) — Plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Uma tela "Dados" por tabela, aberta da tela do `ratt db` (`e`) e do canvas (`v`), onde a pessoa insere linhas por formulário, monta um filtro (`WHERE`) sem digitar SQL, e altera, apaga ou tira duplicatas das linhas filtradas — tudo no mesmo rascunho do canvas, com o SQL à vista, contagens antes, confirmação, ensaio e transação única.

**Architecture:** O rascunho sai do canvas para uma **sessão de rascunho** por banco+schema, guardada na aplicação e dividida entre o canvas e a tela Dados; o painel do SQL e as ações aplicar/ensaio/exportar/desfazer viram um pedaço comum (`painel.py`). Dois módulos puros novos: `filtro.py` (a gramática → `WHERE` com literais citados, e o que os avisos precisam saber) e as **operações de dados** em `rascunho.py` (inserir, alterar, apagar, apagar duplicatas), com ids como as da fase 1. As contagens e amostras ficam em `checagem.py`, sempre em transação somente leitura. A tela nova (`tela_dados.py`) e seus formulários (`formularios_dados.py`) só exibem e montam.

**Tech Stack:** Python ≥ 3.9, Textual (8.2.8 instalado), rich, psycopg 3, pytest.

**Spec:** `docs/superpowers/specs/2026-11-02-dados-design.md` — leia antes de qualquer tarefa. A fase 1 (`docs/superpowers/specs/2026-11-01-canvas-db-design.md`) continua valendo.

## Global Constraints

- Python ≥ 3.9: `from __future__ import annotations`, sem `match`, sem `X | Y` em tempo de execução. Sem dependências novas.
- Todo texto de interface em `src/ratt/db/idioma.py` (`"pt"` e `"en"`); prefixos novos: `dados.` (tela/formulários), `filtro.` (operadores, transformações, descrições), `op.` (descrição das operações novas), `chk.` (avisos novos).
- Nomes no SQL sempre por `rascunho.ident()` e **sempre com schema** (`rascunho.nome_tabela`). **Valores digitados nunca entram crus**: só por `filtro.literal(texto, tipo)`. A única exceção é o `WHERE` escrito como texto pela pessoa.
- Checagens: só `SELECT`, em transação **somente leitura** (`SET TRANSACTION READ ONLY`) com `statement_timeout` de 2 s; tempo esgotado → `None` e o aviso `chk.sem_tempo`.
- Nada vai ao banco fora do aplicar/ensaio. Uma operação de dados nunca entra no rascunho sem a contagem (ou o "não deu para contar") ter sido mostrada.
- PostgreSQL 13+. Teclas e textos fixados no spec ("Decisões que tomei").
- Testes: `.venv/bin/python -m pytest tests -q -W error` verde e sem avisos. Testes com PostgreSQL usam o fixture `banco` (banco descartável; nunca tocar outros bancos).
- Commits pequenos, em português, terminando com `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. `git add` só dos arquivos tocados.

## Review Focus

1. **Valores com aspas, `%`, `_`, `\` e acentos** (`O'Brien`, `50%`, `a_b`, `C:\x`, `ação`) num filtro "contém/começa com", num INSERT ou num valor fixo de alterar: o SQL roda e pega exatamente o que a pessoa digitou. → testes em Task 3 (puro) e Task 4 (PostgreSQL).
2. **Filtro sobre coluna que aceita vazio** com `≠`, "não está na lista", `<`, ou condição negada: o aviso diz quantas linhas com vazio ficam de fora; "não está na lista" com vazio na lista avisa que não pega nada. → Task 3 e Task 5.
3. **Tabela com mudança estrutural pendente no rascunho** (coluna criada/renomeada ainda não aplicada): a tela Dados não dá erro; diz "só depois de aplicar"; contagens marcadas "aproximadas" quando há operação anterior na mesma tabela. → Task 7.
4. **Tabela grande** (milhões de linhas): contagem e amostra estouram o tempo → "não deu para contar a tempo", a grade continua paginando, o formulário não trava. → Task 5 e Task 9.
5. **Tabela sem chave primária** (duplicatas, ordem da grade, apagar): duplicatas usam `ctid` com aviso; a grade pagina sem `ORDER BY` estável e diz isso. → Task 4 e Task 9.

### Task 3: O filtro (puro)

**Files:**
- Create: `src/ratt/db/filtro.py`
- Modify: `src/ratt/db/idioma.py` (`filtro.*`)
- Test: `tests/test_dados.py`

**Interfaces:**
- Produces:
  - `@dataclass Condicao(coluna: str, operador: str, valores: List[str] = [], transformacao: str = "", negar: bool = False, diferenciar: bool = False, outra_coluna: Optional[str] = None, existe: Optional[Existe] = None)` — `coluna` é id de coluna (ou `""` quando `existe` está preenchido).
  - `@dataclass Existe(ligacao: str, condicoes: List[Condicao] = [], nao: bool = False)` — `ligacao` é id de `Ligacao` que sai ou chega na tabela; as condições são sobre a **outra** tabela.
  - `@dataclass Filtro(condicoes: List[Condicao] = [], conectivo: str = "E", texto: Optional[str] = None)`; `vazio(self) -> bool`.
  - `familia(tipo: str) -> str` ∈ `"texto"`, `"numero"`, `"data"`, `"booleano"`, `"outro"` (reaproveite `checagem._familia`: mova para cá e importe lá).
  - `transformacoes(tipo: str) -> List[str]` e `operadores(tipo: str, transformacao: str = "") -> List[str]` — as listas do spec, nesta ordem e com estas chaves:
    - transformações: texto → `minusculas`, `trim`, `tamanho`; data → `mes`, `ano`, `dia_semana`, `dia`, `so_data` (só para timestamp).
    - operadores (família depois da transformação: `tamanho`, `mes`, `ano`, `dia_semana`, `dia` → número; `so_data` → data; `minusculas`/`trim` → texto):
      todos: `igual`, `diferente`, `vazio`, `preenchido`, `na_lista`, `fora_lista`;
      texto: + `contem`, `comeca`, `termina`, `igual_sem_caixa`;
      número: + `menor`, `menor_igual`, `maior`, `maior_igual`, `entre`;
      data: + `antes`, `depois`, `entre`, `ha_mais_de`, `nos_ultimos`;
      booleano: só `verdadeiro`, `falso`, `vazio`, `preenchido`.
  - `literal(texto: str, tipo: str) -> str` — número (`^-?\d+(\.\d+)?$`) sai sem aspas; booleano (`sim/não/true/false/t/f/1/0`) sai `TRUE`/`FALSE`; o resto sai como literal citado (`'O''Brien'`); `ValueError` para número inválido numa coluna numérica.
  - `padrao_like(texto: str, onde: str) -> str` — escapa `\`, `%`, `_` e monta `'%x%'`/`'x%'`/`'%x'`.
  - `where(f: Filtro, m: Modelo, tabela_id: str) -> str` — a expressão (sem a palavra `WHERE`); `""` para filtro vazio; com `texto`, devolve o texto entre parênteses. Colunas da tabela principal saem qualificadas (`public.pessoas.nome`) só dentro de `EXISTS`; fora, sem qualificação.
  - `validar_texto(texto: str) -> None` — `ValueError` se o texto tiver `;` fora de aspas/comentário, comentário `--`/`/*`, ou não for uma expressão só (use `rodar.dividir(f"SELECT 1 WHERE {texto};")` e exija um comando).
  - `descricao(f: Filtro, m: Modelo, tabela_id: str) -> str` (curta, idioma) e `descricao_condicao(c, m, tabela_id) -> str`.
  - `refere(f: Filtro, tabela_id: str) -> Set[str]` — ids de colunas e ligações usados (com `texto`: só `{tabela_id}`).
  - `deixa_vazios_de_fora(f: Filtro, m: Modelo, tabela_id: str) -> List[str]` — ids das colunas anuláveis (`obrigatoria=False`) de condições cujo operador não é `vazio`/`preenchido`/`verdadeiro`/`falso` (ou que estão negadas). Com `texto`: `[]`.
  - `fora_lista_com_vazio(f: Filtro) -> bool` — alguma `fora_lista` tem valor vazio (`""`) na lista.
  - `para_dict(f) -> dict` / `de_dict(d) -> Filtro` (`ValueError` para chaves desconhecidas).

SQL de cada operador (`c` = coluna depois da transformação; `v` = `literal(valor, tipo)`):

| operador | SQL |
|---|---|
| `igual` / `diferente` | `c = v` / `c <> v` (com `outra_coluna`: o lado direito é a outra coluna) |
| `vazio` | texto: `(c IS NULL OR trim(c) = '')`; outros: `c IS NULL` |
| `preenchido` | texto: `(c IS NOT NULL AND trim(c) <> '')`; outros: `c IS NOT NULL` |
| `na_lista` / `fora_lista` | `c IN (v1, v2)` / `c NOT IN (v1, v2)` |
| `contem` / `comeca` / `termina` | `c ILIKE '%x%'` / `'x%'` / `'%x'` (com `diferenciar`: `LIKE`) |
| `igual_sem_caixa` | `lower(c) = lower(v)` |
| `menor`…`maior_igual` | `<`, `<=`, `>`, `>=` |
| `entre` | `c BETWEEN v1 AND v2` |
| `antes` / `depois` | `c < v` / `c > v` |
| `ha_mais_de` / `nos_ultimos` | `c < now() - interval 'N unidade'` / `c >= now() - interval 'N unidade'`; `valores = [N, unidade]`, unidade ∈ `dias`→`days`, `meses`→`months`, `anos`→`years`; N inteiro positivo |
| `verdadeiro` / `falso` | `c IS TRUE` / `c IS FALSE` |

Transformações: `minusculas` → `lower(c)`, `trim` → `trim(c)`, `tamanho` → `length(c)`, `mes` → `extract(month FROM c)`, `ano` → `extract(year FROM c)`, `dia_semana` → `extract(isodow FROM c)`, `dia` → `extract(day FROM c)`, `so_data` → `c::date`. `negar` → `NOT (…)`. Conectivo `E` → `AND`, `OU` → `OR`, cada condição entre parênteses quando há mais de uma. `existe` → `[NOT] EXISTS (SELECT 1 FROM outra WHERE outra.fk = principal.pk [AND …])` com as colunas da ligação.
